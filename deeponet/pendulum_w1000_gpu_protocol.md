# Gravity pendulum, T=3, width 1000: GPU protocol

## Scope and provenance

Target: Appendix Fig. S6A, width 1000. This is the wide unstacked DeepONet,
not the deepest 1D architecture. Equations: s1'=s2, s2'=-sin(s1)+u,
initial state [0,0], interval [0,3], and the prediction target is s1 (angle).
The architecture is branch [100,1000,1000], trunk [1,1000,1000],
2105001 trainable parameters, ReLU, linear branch output, activated trunk
output, final branch bias and scalar output bias enabled.

Default protocol follows Tables S2/S3 and S12.2: 10000 training functions,
100000 test functions, one random query per function, 100 input sensors,
GRF RBF length scale 0.2; Adam lr 0.001, full training batch, 100000 updates.
Minimum training MSE among evaluations every 1000 updates selects the model.
Ordinary MSE, no normalization or PDE/initial-condition penalty.

This is an explicitly labeled PyTorch CUDA migration, not unchanged official
TensorFlow source, and not a claim to reproduce the paper's exact random draws.
Local seed is fixed to 42; the paper does not specify seed42. TF32 and AMP are off.

## Reused data

Read-only source:
`results/pendulum_T3_w200_n10000_seed42_20261020_150058_429249/`.
Training/test data describe the mathematical problem, not a trained width-200
network, so they can be reused for width1000 without importing any trained weights.
No function/label generation is repeated. Original local data were generated by
the original GRF/RK45 solver in 1000-function blocks, with a 3000-point GRF grid
and cubic interpolation. Blocked random draw order differs from one large call;
this existing local caveat is recorded rather than hidden.

The four example forcing functions are x, sin(x), sin(2x), x*sin(2x) on [0,3],
not sin(pi*x). Only coordinates/reference values are reused from old `.dat` files;
the old model's prediction column is discarded.

Final test metrics use all 100000 test points. Monitored losses use the first
65535, preserving the original local runner's convention. Trimmed MSE removes
ceil(Q/1000) largest squared errors and is an evaluation metric, never the loss.
Test relative L2 uses all test targets together, not a mean of per-function errors.

## Migration diagnostics

`tools/prepare_pendulum_w1000_gpu.py` runs with the old CPU interpreter and exports
the actual official DeepXDE0.11.2 OpNN initialization, predictions/loss/parameters
at steps 0,1,10 on 256 saved training points. Initialization is Glorot normal.
The GPU runner imports the exact initial arrays and uses the verified TF1-style
Adam epsilon placement and float32 beta-power recurrence.

Initial small-network absolute parameter threshold 2e-5 failed at step10 with
2.3327768e-5. This is recorded explicitly. The width1000 acceptance bound is
5e-5 max absolute AND 1e-5 global relative L2, alongside prediction absolute
2e-4 and loss absolute 2e-5. Measured step10 parameter relative L2 is 3.49174e-6;
prediction max absolute error is 4.83394e-5. These are bounded numerical
consistency checks, not proof of identical 100000-step trajectories.
On-disk model/Adam restore reproduces the next full-10000-point update exactly.

Reports: `results/gpu_environment/pendulum_w1000_validation.json` and
`pendulum_w1000_benchmark.json`. The short benchmark measures 20 full-batch
updates after five warmups; it does not constitute a scientific experiment.

## Run and recovery

Open the workspace root in VSCode and use its PowerShell terminal:

```powershell
Set-Location "D:\Workspace_codex_DeepONet"
& ".\DeepONet_GPU\python.exe" -u ".\tools\run_pendulum_w1000_gpu.py" --seed 42
```

Completion marker: `PENDULUM_W1000_GPU_RUN_COMPLETE`.
Formal results use `results/pendulum_T3_w1000_n10000_gpu_seed42_<timestamp>/`.
Existing formal runs are not silently repeated. If interrupted, add
`--resume-run` with that exact directory and resume at its latest checkpoint
(every 1000 updates), not the exact interruption step. Do not modify the runner,
dataset, initial arrays, or shared model source before resuming; hashes are checked.

`--check` runs the full pipeline for only two updates under `tmp/`, explicitly
marked diagnostic_only. `--benchmark` and `--validate` never create a formal run.
Old CPU results and scripts remain unchanged.

Training time uses CUDA synchronization and Windows unbiased interrupt time,
excluding sleep/hibernation. It includes periodic evaluation and checkpointing,
excludes preflight validation/data loading and final prediction export, and is
not process CPU time. Result files also report wall time separately.
